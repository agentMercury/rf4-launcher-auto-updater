## 这个项目解决什么问题

`RF4钓鱼登录器.exe`（约 52.7 MB）本身**没有**自动更新。作者发新版本时，它启动只会弹窗告诉你：

- `游戏文件版本不匹配：当前支持 RF4 4.0.25034，文件未替换`
- `登录器版本需要更新，请到网盘下载最新版`
- `发现新版本 vX · Build N，请到网盘下载（不自动更新）`

然后你得人工走一遍这个流程：

```
弹窗提示版本不匹配
  → 手动打开作者网站 → 点「下载插件」
  → 跳转蓝奏云文件夹页 → 点文件 → 过广告/验证页 → 下载 52.7 MB
  → 解压/覆盖游戏目录里的旧 RF4钓鱼登录器.exe
  → 再重新启动登录器
```

本项目把上面这一整套（除了作者自己的服务器）全部自动化：**检测 → 下载 → 校验 → 备份 → 替换 → 启动**，
你只需要双击一个快捷方式，或者干脆什么都不用做（后台监控模式）。

## 特性

- **全自动**：一处入口搞定检测、下载、替换、启动登录器，全程无需浏览器。
- **纯标准库**：只用 `urllib`、`http.cookiejar`、`hashlib`、`tkinter` 等 Python 自带模块，不需要 `pip install` 任何东西。
- **零侵入**：不注入、不修改游戏进程、不改游戏文件；只替换登录器 exe 这一个文件。
- **双重校验**：下载完比对 SHA-256；替换前读取 exe 内嵌版本号，**拒绝降级**（防网盘里残留旧文件把人带回旧版）。
- **事务式替换 + 自动回滚**：先备份、再改名、最后移入；任何一步失败都会把旧文件还原，不会出现「半新半旧」。
- **历史留档**：每次替换前的版本都留在 `backups/`，随时可以手工换回去。
- **信号驱动**：直接读登录器自己写的运行日志来判断「是不是又在喊更新」，不抓窗口、不模拟点击，稳定可靠。
- **多入口**：图形界面（双击 bat）、后台常驻监控（可开机自启）、命令行（脚本/计划任务可调）。
- **幂等安全**：重复运行、重复双击都不会出问题；已经是最新版就直接启动游戏。

## 工作原理

### 1. 触发信号：登录器自己的运行日志

登录器每次启动都会在 `%APPDATA%\RF4LocalLauncher\` 下写一个 `launcher-<时间戳>.json`，
弹窗时的那次运行记录长这样：

```json
{
  "TimeUTC": "2026-11-16T10:06:12.123456789Z",
  "ExitStatus": 1,
  "Error": "游戏文件版本不匹配：当前支持 RF4 4.0.25034，文件未替换"
}
```

判定规则很朴素：`ExitStatus == 1` 且 `Error` 里出现 **版本不匹配** 或 **网盘**，就说明登录器在喊更新。
更新器每隔 30 秒扫一次这个目录（只认比上次见过的新文件，不会重复触发），比去抓窗口标题稳定得多。

> 顺带一提：登录器的选择区服窗口其实是它自己用 PowerShell + WinForms 渲染的，用 `FindWindow` 之类的办法也能抓到，但没必要 —— 日志是它自己写的权威信号。

### 2. 版本号从哪来

exe 里内嵌了版本字符串：

```
rf4-4.0.25034-lan-v154-required-launcher
                  ^^^^ 这就是登录器版本号
```

更新器直接在二进制里搜这个模式取 `v154`：**本地版本**从已安装的 exe 读，**远端版本**从刚下载下来的 exe 读。
这样判断的是「文件真实内容」而不是某个时间戳或网页文字，网盘上文件被替换、同名不同版也能认出来。

### 3. 下载链路（蓝奏云，全部实测跑通）

```
https://wwbxt.lanzoul.com/b0nyv844f          登录插件下载（文件夹页）
  ├─ POST filemoreajax.php?file=<fid>        列出文件：id / 文件名 / 大小 / 更新时间
  ├─ 分享短链页 https://wwbxt.lanzoul.com/<id>
  │    └─ iframe /fn 页                     取 wp_sign、ajaxdata、fid
  ├─ POST ajaxfile.php  action=downprocess  kd=1 → 下载域名 + 地址参数
  ├─ GET 下载直链                           ↓ 阿里 WAF：acw_sc__v2 纯算法求解
  │                                          cookie 设好，重试同一 URL
  ├─ 蓝奏云二次验证页（interstitial）        ↓ 等 6 秒，POST ajax.php  el=2
  ├─ 真实文件直链（30 分钟时效）
  └─ 流式下载 + SHA-256 校验
```

其中几个坑点（都已解决，写在这里省得后人再踩）：

- **阿里 WAF `acw_sc__v2`**：cookie 值可以用纯算法算出来 —— `hexxor(reorder(arg1, M), P)`，
  `M` 是 40 位置换表、`P` 是固定串。不需要 JS 引擎、不需要无头浏览器，0.1 秒解完。
  前提是处理 gzip 压缩的挑战页（响应头不一定诚实），并把这个 cookie 按**精确主机名**设置才对得上。
- **蓝奏云二次验证页**：拿到 4.8 KB 的验证页后**必须先等约 6 秒**（页面自己的加载动画时间）再提交 `el=2`，
  立刻提交只会拿到 `{"zt":1,"url":"?SignError"}`；而 `el=1 / el=3` 那两条路要真验证码，走不通。
  另外提交地址是**相对当前 URL 目录**的 `ajax.php`，不能简单字符串拼接（query 里带斜杠会拼出 400）。
- **混淆变量名会轮换**：文件夹页里 `t` / `k` 两个 token 对应的 JS 变量名（曾经是 `ibjk9n`、`_hhwbg`，
  后来变成 `iblpff`、`_hk1h8`）作者随时会换。所以解析不硬编码变量名，而是先在 ajax data 块里找到
  `'t':<name>` / `'k':<name>` 的引用名，再回查 `var <name> = '...'`，最后还有按值形态（纯数字 / 32 位 hex）兜底。
- **多镜像域重试**：`wwbxt.lanzoul.com` / `wwbxt.lanzoui.com` / `wwbxt.lanzn.com` 三个域名结构一致，
  某个域解析失败或 DNS 挂了会自动换下一个。
- **下载条目的 id 会变**：每次作者更新，网盘里那个文件的 id 都变（如 `iLN4z4g5ohyb`），所以每次都重新列目录，不缓存 id。

### 4. 替换事务（这是唯一会动你磁盘的步骤）

```
1. 备份   RF4钓鱼登录器.exe  →  backups/RF4钓鱼登录器.v<旧版本>.<时间戳>.bak.exe
2. 改名   RF4钓鱼登录器.exe  →  RF4钓鱼登录器.exe.old     （Windows 允许重命名正在运行的 exe）
3. 移入   下载好的新文件     →  RF4钓鱼登录器.exe
4. 失败   os.replace(.old, RF4钓鱼登录器.exe) 回滚
5. 清理   删掉 .old（登录器正在运行时可能删不掉，忽略即可，下次启动前也无害）
```

三个前置判断：

- 本地压根没有登录器 → 直接安装。
- 下载文件与本地 SHA-256 相同 → 视为「已是最新」，什么都不做。
- 新版本号 < 本地版本号 → **直接拒绝**，报「远端版本低于本地，拒绝降级」。

## 快速开始

### 前置条件

- Windows 10 / 11
- Python 3（3.6+ 均可；只要标准库，GUI 需要 tkinter，官方安装包默认自带）
- 游戏目录里有 `rf4_x64.exe` 和 `RF4钓鱼登录器.exe`

### 三步装好

**1. 放进去** —— 把整个 `rf4-auto-update` 文件夹放进游戏目录，和游戏本体同级：

```
E:\ChineseFishing4\
├─ rf4_x64.exe
├─ RF4钓鱼登录器.exe
├─ package.conf
└─ rf4-auto-update\          ← 整个文件夹放这里
   ├─ rf4_updater.py
   ├─ rf4_updater_gui.py
   └─ ...
```

> 更新器就是靠「上一级目录里有 `rf4_x64.exe`」来认游戏目录的，所以位置放对了就不需要任何配置。

**2. 双击 `RF4-update.bat`** —— 弹出更新器窗口，自动判断要不要更新；需要更新就下载替换，
然后 3 秒倒计时自动启动登录器，更新器自己关窗消失。

**3. （可选）双击 `make-shortcut.bat`** —— 在桌面生成一个图标为 `cf4.ico`、名字为 **Chinese Fishing 4** 的快捷方式，
以后就拿它当游戏入口，双击 = 检查更新 + 启动游戏。

**（可选）开机自启** —— 双击 `start-watcher.bat` 开后台监控；把它的快捷方式放进 `shell:startup`
（Win+R 输入 `shell:startup` 回车打开的那个文件夹）就实现登录时自动启动监控。

## 三种用法

### 一、图形界面 `rf4_updater_gui.py`（推荐日常用）

双击 `RF4-update.bat` 或桌面快捷方式即可。行为：

- 开窗后立刻开始判断：需要更新 → 下载、校验、替换；已是最新 → 直接进入启动流程。
- 界面会显示四条信息：**游戏目录** / **本地登录器**（版本+大小）/ **网盘版本** / **状态**。
- 有 10 段进度带实时显示当前阶段（定位目录、列网盘、下载、过验证、校验、备份、替换……）。
- 4 个按钮：`取消`（停手，什么都不改）/ `重试` / `启动登录器` / `关闭`。
- 更新成功后 3 秒自动启动登录器并退出；出错时窗口**保留**并显示错误原因，方便看日志。
- 任意异常都会写进 `updater_error.log`，不会静默失败。

窗口是按「Chinese Fishing 4」湖边垂钓主题手绘的（夜色湖面、芦苇、浮漂、鱼影），纯 tkinter Canvas 画的，没有图片资源依赖。

### 二、后台监控 `watch`（一次开，长期免管）

```bat
start-watcher.bat
rem 等价于: pythonw rf4_updater.py watch
```

- 隐藏窗口常驻，30 秒扫一次登录器日志（轻量，纯文件读取）。
- 发现「版本不匹配 / 网盘」新日志 → 触发一次完整更新，并启动登录器。
- 每 30 分钟（`POLL_INTERVAL`）主动查一次网盘，即使你没点游戏也能提前下好。
- **首次启动不追溯**：只把「启动之后新产生的」日志当作信号，不会因为历史日志立刻乱更新一遍。
- 不想常驻也可以改用 `pythonw rf4_updater.py new-mismatch`（带 1 小时冷却），配合 Windows 计划任务每 5 分钟跑一次。
- 更新时若发现远端与本地完全一致（同 SHA-256），只记状态不下手，不会反复重下。

### 三、命令行 `rf4_updater.py`

| 命令 | 作用 |
| --- | --- |
| `python rf4_updater.py` | 等同 `status` |
| `python rf4_updater.py status` | 打印游戏目录、本地版本、补丁要求版本、是否匹配 |
| `python rf4_updater.py check` | 只查网盘有没有新版（列文件 + 报版本），不下载不替换 |
| `python rf4_updater.py update` | 完整流程：检查 → 下载 → 校验 → 替换 |
| `python rf4_updater.py update --no-replace` | 只下载和校验，把文件留在 `downloads/`，不动已装的 |
| `python rf4_updater.py watch` | 常驻监控（前台，能看输出；bat 里用 pythonw 隐藏） |
| `python rf4_updater.py install <文件>` | 手动安装一个已下载的 exe（照样校验版本，拒绝降级） |
| `python rf4_updater.py new-mismatch` | 一次性检查（给计划任务用）：仅在出现**新的**不匹配日志且距上次成功更新超过 1 小时时才更新，否则直接退出 |

示例输出：

```
> python rf4_updater.py status
登录器      : E:\ChineseFishing4\RF4钓鱼登录器.exe
本地大小    : 55304192 bytes
本地要求版本: v154
补丁要求版本: rf4-4.0.25034-lan-v153-required-launcher
匹配状态    : OK 可正常启动
上次网盘文件: iLN4z4g5ohyb
上次自动更新: {"at": "2026-11-16T12:33:33", "to_v": 154, "result": "same", "sha256": "b9a50eb3..."}
```

> 本地 v154 高于补丁要求的 v153 是正常现象：登录器向下兼容，只要不低于它内嵌的 required 版本就不会弹版本不匹配。

| --- | --- |

## 配置项

### 环境变量（可选）

| 变量 | 作用 |
| --- | --- |
| `RF4_GAME_DIR` | 手动指定游戏目录（优先级最高，找不到目录时用） |
| `RF4_DRY_RUN=1` | 演练模式：GUI 不真的启动登录器（调试界面用） |

### 游戏目录定位顺序

1. 环境变量 `RF4_GAME_DIR`
2. `updater_state.json` 里上次记住的 `game_dir`
3. `rf4-auto-update` 的上一级目录（本身是游戏目录优先，其次扫它的子目录）
4. 登录器自己的 `%APPDATA%\RF4LocalLauncher\settings.json` 里的 `gameDir`

全部失败才报错（并提示把文件夹放进游戏目录或设 `RF4_GAME_DIR`）。
查找范围被严格限制在这几处，**不会去全盘搜索或往别处写文件**。

### 源码里的常量（`rf4_updater.py` 顶部）

| 常量 | 默认值 | 含义 |
| --- | --- | --- |
| `FOLDER_PATH` | `/b0nyv844f` | 蓝奏云「登录插件下载」文件夹 |
| `FOLDER_FID` / `FOLDER_UID` | `11479625` / `1506996` | 文件夹内部 id 与 uid |
| `HOSTS` | lanzoul / lanzoui / lanzn | 主域 + 镜像域，依次重试 |
| `TARGET_NAME` | `RF4钓鱼登录器.exe` | 要替换的目标文件名 |
| `POLL_INTERVAL` | `30 * 60` 秒 | watch 模式主动查网盘的间隔 |
| `GATE_DELAY` | `6` 秒 | 二次验证页提交前的等待（不能更短） |
| `VER_RE` | `rf4-4\.0\.25034-lan-v(\d+)-required-launcher` | 版本号提取正则 |
| `UA` | Chrome/131 | 伪装的浏览器 UA |

> 游戏大版本号变了（`4.0.25034` → 其它）时，`VER_RE` 也要跟着改，否则读不到版本号。

## 状态、日志与备份

- **看现在什么情况**：双击 `show-status.bat`，或 `python rf4_updater.py status`。
- **看历史**：`updater.log`，每次替换会记一行类似
  `替换成功 sha256 ace58fdbf8f244b1 -> b9a50eb32522dc8f, v153 -> v154`。
- **想回滚**：把 `backups/` 里对应的 `.bak.exe` 改名回 `RF4钓鱼登录器.exe` 覆盖回去即可
  （或者 `python rf4_updater.py install backups\xxx.bak.exe` —— 注意它同样会拒绝降级，
  真降级请直接手工复制）。
- **清理**：`downloads/` 和 `backups/` 可以随时清空，只影响回滚能力。

## 常见问题

**Q：双击 bat 闪一下就没了？**
说明没找到 `pythonw.exe`。装个 Python 3 并勾选 Add to PATH，或者直接改 bat 顶部的兜底路径。
可以先双击 `show-status.bat` 看报错（它带 pause，不会闪退）。

**Q：提示「找不到 RF4 游戏目录」？**
把整个 `rf4-auto-update` 文件夹放到和 `rf4_x64.exe` 同一个目录下，或设置 `RF4_GAME_DIR` 环境变量指向游戏目录。

**Q：会不会把我游戏搞坏？**
不会碰游戏本体（`rf4_x64.exe`、`GameAssembly.dll`、`rf4_x64_Data\` 一律不写），只替换 `RF4钓鱼登录器.exe` 这一个文件，
替换前有备份，替换有回滚。真出问题用 `backups/` 里的文件覆盖回去就行。

**Q：那个「补丁 dll」和 `.rf4-local` 目录呢？**
那些是登录器**自己**管的（它启动时会 prepared 补丁并写 `.rf4-local\state.json`），本项目不管也不该管 —— 
把登录器换成新版后，它自己会把补丁对齐。

**Q：蓝奏云改版了怎么办？**
报错会明确写在 `updater.log` 里（例如「页面 token 解析失败」），此时需要更新解析逻辑。
好在解析带三重兜底 + 三镜像重试，一般的小改版不至于直接挂。

**Q：需要管理员权限吗？**
不需要，除非游戏装在 `C:\Program Files` 之类受保护目录。

**Q：杀毒软件 / SmartScreen 报警？**
本项目是未签名的 Python 脚本，又会下载一个未签名的 exe，触发提示是正常的。
所有代码都在仓库里可以直接读，下载后也会校验 SHA-256 —— 但这个校验只保证「文件下完整了」，不是「来源可信」。

**Q：多久检查一次合适？**
日常用图形界面入口（每次点游戏顺便查）；想全自动就开 `watch`（30 分钟一次网盘，30 秒一次日志）。
频率再高没有意义 —— 作者发版本身就是以天/周计的。

**Q：为什么不用官方的 `launcher-updates/stable.json`？**
作者确实另有一个签名更新源（`https://www.kezongsyst.com/launcher-updates/stable.json`，
带 Ed25519 签名，指向约 9.4 MB 的精简版 exe）。但网盘上那个 52.7 MB 才是**玩家实际在用的打包版**，
两者体积差 5 倍，打包形态不同。本项目选择跟随网盘版以保持一致，避免出现「换了精简版结果缺东西」的情况。

## 已知限制

- 依赖蓝奏云页面的结构（作者/平台随时可能改版），也依赖登录器的日志格式（登录器大版本更新可能变）。
- 只处理 `RF4钓鱼登录器.exe` 一个文件；游戏本体、补丁 dll 都不归它管。
- 版本号提取依赖正则里的游戏大版本号 `4.0.25034`，游戏本体大版本变了要手工改 `VER_RE`。
- 没有数字签名校验（作者没签名，也没有可校验的公钥链），安全性上限就是「SHA-256 传输完整性」。
- 只测过 Windows；理论上有 Python 的其它平台能跑下载逻辑，但替换事务和 bat 都是 Windows 专用。
